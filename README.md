# AIMO LLM Solver

一个为奥林匹克级数学推理任务优化的生产级推理系统，融合了大语言模型、有状态工具调用和熵加权自一致性投票机制。

## 项目概览

本项目是 **AI 数学奥林匹克竞赛（AIMO）第三届 Progress Prize** 的完整解决方案——这是一个高难度基准，评估模型在从国家级到 IMO（国际数学奥林匹克）标准的数学问题上的推理能力。

**核心成就**：
- 在严格的离线环保和时间约束下处理 50+ 道奥数级问题
- 通过多路径采样和置信度加权聚合实现稳定性
- 在双路 rerun 私榜评测中保持稳定性和可复现性

## 竞赛背景

AIMO3 的独特约束塑造了整个解决方案的设计：

- **答案空间**：[0, 99999] 范围内的整数（非典型分类问题）
- **评估机制**：独特的"双路运行"私榜评分规则
  - 两次都正确：+1 分
  - 一正一错：+0.5 分
  - 两次都错：0 分
  - 这要求**稳定性优于原始准确度**
- **运行环境**：Kaggle 离线 Notebook
  - 无网络访问 → 离线依赖打包
  - 单 GPU（~40GB 显存）
  - 严格 5 小时执行限制（~17,400 秒用于处理 50 道题）
  - 单题动态预算管理

## 解决方案架构

### 核心流程

**第一阶段：问题输入与多路径管理**

1. 接收问题（题目 ID + LaTeX 格式文本）
2. 初始化多路径管理器（控制并行度 = 8，Early Stop 阈值 = 4 票）
3. 为每条推理路径分配独占的 Jupyter kernel

**第二阶段：单路径推理循环（重复 1-8 次）**

每条推理路径执行以下步骤：

| 步骤 | 内容 | 说明 |
|------|------|------|
| 1 | Harmony 对话构建 | 组装系统提示 + 题目 + 工具配置 |
| 2 | vLLM 流式推理 | GPT-OSS-120B 生成推理文本 |
| 3 | 工具调用检测 | 检查是否生成工具调用标记 |
| 4a | 工具执行（如需要） | 在持久 Jupyter kernel 中执行 Python 代码 |
| 4b | 继续推理（如需要） | 将工具结果回填给模型 |
| 5 | 答案抽取 | 从输出中提取 `\boxed{N}` 或最后的数字 |
| 6 | 置信度评分 | 基于 token logprobs 计算综合置信度 |

**第三阶段：投票聚合**

- 收集所有有效答案及其置信度
- 使用 `1/entropy` 加权投票（而非简单多数）
- Early Stop：任一答案累计 4 票时立即停止其他推理
- 返回最高分答案

**最终输出**

- 单个整数答案（范围 0-99999）
- 以及诊断信息（尝试次数、最高置信度、耗时等）

### 技术创新点

1. **工具增强推理**
   - 有状态 Jupyter 内核池（16 个持久内核）
   - 单条推理链中的多轮计算
   - 支持库：`math`、`numpy`、`sympy`、`mpmath`、`itertools`、`collections`

2. **熵加权自一致性投票**
   - 超越简单多数投票
   - 利用生成过程中的 token 级 logprobs
   - 区分"多个低质量路径碰巧同答"与"少数高置信路径得出答案"

3. **Harmony 协议集成**
   - 通过 Harmony token 协议的原生工具调用
   - 正确处理助手动作、频道和工具接收者
   - 流式响应解析

4. **运行时工程优化**
   - 离线 wheel 依赖安装
   - OS PageCache 模型预热加速冷启
   - FP8 KV Cache 和 vLLM Prefix Caching
   - 单题动态时间预算
   - 显式资源清理

## 核心配置

| 模块 | 配置值 |
|------|--------|
| 基础模型 | GPT-OSS-120B |
| 推理服务 | vLLM OpenAI API |
| 上下文窗口 | 65,536 tokens |
| 采样参数 | T=1.0, min_p=0.02, 每路不同 seed |
| 每题尝试数 | 8（并行） |
| 提前停止阈值 | 4 票 |
| 内核池大小 | 16 个持久 Jupyter 内核 |
| 单次最大输出 | 2,048 tokens |
| KV Cache 精度 | FP8 (E4M3) |
| GPU 显存占用率 | 0.96 |

## 核心发现

### 多路径采样的收益
- 通过多样化降低单链失败概率
- 数学推理失败通常不在于理解而在于路径选择
- 8 条并行路径有效探索解空间

### 熵加权投票的有效性
- 捕捉生成过程中的模型置信度
- 对大答案空间优于多数投票
- 降低异常预测的影响

### 时间预算管理
- 动态分配防止前面的题消耗全部时间
- 经验验证最小单题预算：270 秒
- 提前停止节省尾部推理时间

### 双路 rerun 稳定性
- 着重于**跨 rerun 的可复现性**
- 资源清理防止状态泄漏
- 确定性种子保证采样一致性
